# Task: RUNNER-02 — Add production service templates for web and runner

## Context

Flow has a `docker-compose.yml` with a web service but no runner service. The new `flow_app.runner` module (RUNNER-01) needs a production service template. There's also no systemd service file for either the web server or the runner.

This task adds Docker Compose and systemd examples that make the server deployment obvious for a new user and for our live dogfood install.

## What Exists

1. **`docker-compose.yml`** — has a `flow` service (web only), no runner profile
2. **`Dockerfile`** — builds Flow, runs uvicorn
3. **`.env.example`** — documents env vars but not runner-specific ones
4. **`flow_app/runner.py`** (on branch `codex/flow-f563-runner`, NOT yet on main) — unified runner with `main()` CLI, `--once`, `--loop`, `--stale-recovery-only`, `--dry-run`, `--profiles`, `--interval`, `--base-url`, `--api-key`
5. **`flow_app/dispatcher_cli.py`** — existing single-agent CLI (separate from runner)
6. **`flow_app/webhook_cli.py`** — webhook delivery CLI with `--loop`, `--dry-run`
7. **`pyproject.toml`** — has no `[project.scripts]` entry points

## What to Implement

### 1. Update `docker-compose.yml` — add runner service profile

Add a `flow-runner` service that shares the same data volume as the web service:

```yaml
services:
  flow:
    build: .
    ports:
      - "8100:8100"
    volumes:
      - flow-data:/data
    environment:
      - FLOW_DATABASE_URL=sqlite:////data/flow.sqlite
      - FLOW_DATA_DIR=/data
      - FLOW_DEFAULT_PROJECT=default
      - FLOW_HOST=0.0.0.0
      - FLOW_PORT=8100
      - FLOW_TRUSTED_HEADERS=true
      - FLOW_SESSION_SECRET=change-me-to-something-safe
      - FLOW_SESSION_COOKIE_SECURE=true
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8100/healthz')"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s

  flow-runner:
    build: .
    volumes:
      - flow-data:/data
    environment:
      - FLOW_DATABASE_URL=sqlite:////data/flow.sqlite
      - FLOW_DATA_DIR=/data
      - FLOW_RUNNER_PROFILES=hermes-delegator
      - FLOW_RUNNER_INTERVAL=30
      - FLOW_BASE_URL=http://flow:8100
      - FLOW_API_KEY=change-me-to-a-real-key
    command: ["python", "-m", "flow_app.runner"]

volumes:
  flow-data:
```

Key points:
- `flow-runner` uses the same image and volume as `flow`
- It does NOT expose ports (no web UI needed)
- `FLOW_BASE_URL` points to the web service internally (`http://flow:8100`)
- `FLOW_RUNNER_PROFILES` is comma-separated agent names
- The command is `python -m flow_app.runner` which calls `main()` in the runner module
- Start with `docker compose --profile runner up` or just `docker compose up` (both services default)

### 2. Add `docs/SYSTEMD.md` — systemd service examples

Create a new doc file with production systemd examples for:

**flow-web.service:**
```ini
[Unit]
Description=Flow web server
After=network.target

[Service]
Type=simple
User=flow
Group=flow
WorkingDirectory=/opt/flow
EnvironmentFile=/etc/axis/flow.env
ExecStart=/opt/flow/.venv/bin/python -m uvicorn flow_app.main:app --host 0.0.0.0 --port 8100
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

**flow-runner.service:**
```ini
[Unit]
Description=Flow automation runner
After=network.target flow-web.service

[Service]
Type=simple
User=flow
Group=flow
WorkingDirectory=/opt/flow
EnvironmentFile=/etc/axis/flow.env
ExecStart=/opt/flow/.venv/bin/python -m flow_app.runner
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Key points for the doc:
- Explain same-host/same-volume SQLite requirement: both services must use the same `FLOW_DATABASE_URL` pointing to the same file
- For Docker: shared volume. For systemd: same filesystem path
- Document all runner env vars: `FLOW_RUNNER_PROFILES`, `FLOW_RUNNER_INTERVAL`, `FLOW_BASE_URL`, `FLOW_API_KEY`, `FLOW_DATABASE_URL`, `FLOW_RUNNER_DRY_RUN`
- Note that `FLOW_API_KEY` must be an admin or implementer-scoped key
- Add a section on "Quick smoke test" using `python -m flow_app.runner --once --stale-recovery-only`
- Add a section on "Checking runner health" — `systemctl status flow-runner` and `journalctl -u flow-runner`

### 3. Update `.env.example` — add runner variables

Add these lines after the existing `FLOW_SESSION_COOKIE_SECURE` section:

```env
# Runner configuration (for flow-runner service or python -m flow_app.runner)
# Comma-separated agent profile names to dispatch on each pass
# FLOW_RUNNER_PROFILES=hermes-delegator
# Seconds between runner passes (default: 30)
# FLOW_RUNNER_INTERVAL=30
# Flow API base URL for subprocess dispatch (default: http://127.0.0.1:8100)
# FLOW_BASE_URL=http://127.0.0.1:8100
# Flow API key with implementer or admin role
# FLOW_API_KEY=
# Dry-run mode: log what would happen without executing (default: false)
# FLOW_RUNNER_DRY_RUN=false
```

### 4. Add `[project.scripts]` entry point in `pyproject.toml`

Add a console script entry point so the runner can be invoked as `flow-runner`:

```toml
[project.scripts]
flow-runner = "flow_app.runner:main"
```

This also makes `python -m flow_app.runner` work (the `if __name__ == "__main__"` block at the bottom of runner.py already calls `main()`).

### Important Constraints

- **DO NOT modify** any Python source files except `pyproject.toml` for the entry point
- **DO NOT modify** `flow_app/runner.py` (it's on the RUNNER-01 branch, not yet merged)
- The runner module's `main()` returns an `int` exit code (0 for success) and uses `argparse` — this is sufficient for both `python -m flow_app.runner` and the `flow-runner` entry point
- The Docker Compose runner service must NOT include `FLOW_TRUSTED_HEADERS` or `FLOW_SESSION_SECRET` — those are web-server-only settings
- The systemd `EnvironmentFile` path `/etc/axis/flow.env` matches the existing production deployment convention
- Keep documentation concise and practical — this is an operational guide, not a design doc
