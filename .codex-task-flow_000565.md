# Task: RUNNER-03 — Add first-run bootstrap command

## Context

Flow is a FastAPI + SQLAlchemy kanban service at `/home/nyx/.hermes/projects/flow`. The existing `flow-runner` entry point (in `flow_app/runner.py`) runs the automation loop. We need a new `flow-bootstrap` CLI entry point that sets up a fresh Flow installation.

The project currently has:
- `flow_app/runner.py` — automation runner with `RunnerConfig` dataclass and `main()`
- `flow_app/config.py` — `FlowSettings`, `get_settings()`, `default_database_url()`
- `flow_app/database.py` — `build_engine()`, `build_session_factory()`, `Base`
- `flow_app/models.py` — ORM models: `Project`, `AgentApiKey`, `Agent`, `Task`, `WorkspaceConfig`, `AutomationRule`, `ApiKeyRole`
- `flow_app/repository.py` — `create_project()`, `ensure_project()`, `create_agent_api_key()`, `create_agent()`, `create_automation_rule()`
- `flow_app/schemas.py` — Pydantic models: `ProjectCreate`, `AgentApiKeyCreate`, `AgentCreate`, `AutomationRuleCreate`, `WorkspaceConfigCreate`
- `flow_app/main.py` — `create_app()` with `ensure_compatible_schema(engine)`
- `pyproject.toml` — `[project.scripts]` currently has only `flow-runner = "flow_app.runner:main"`

Key patterns:
- Counter-based IDs: `flow_000001`, `agent_000001`, `key_000001` etc via `generate_counter_id(session, name, prefix)`
- API keys: `flow_` prefix + `secrets.token_urlsafe(32)`, stored as SHA-256 hash
- `ApiKeyRole` enum: `admin`, `architect`, `implementer`, `reviewer`, `read_only`
- `Agent.dispatch_statuses` defaults to `"backlog,todo"` (string of comma-separated statuses)
- Tests use `tmp_path` fixture and `create_app(db_url, trusted_headers=True, session_secret="test-secret-for-testing")`

## What to implement

### 1. New file: `flow_app/bootstrap.py`

Create a `flow-bootstrap` CLI entry point that sets up a fresh Flow installation. The command should:

1. **Create the default project** — using `ensure_project(slug=project_slug)`. Default slug: `default`. Idempotent (skip if exists).
2. **Create API keys** — one admin key and one implementer key. Print the raw key values to stdout so the user can save them. Idempotent: if a key with the same name already exists AND is not revoked, skip creation.
3. **Create a sample smoke-test agent** — a minimal agent profile with `agent_type="cli"`, `command="echo smoke-test"`, `dispatch_statuses="todo"`, `max_concurrency=1`. Idempotent: skip if an agent with the same name exists.
4. **Create a sample workspace config** — name `default`, strategy `scratch_dir`. Idempotent: skip if a workspace config with the same name exists.
5. **Create sample automation rules** — two rules:
   - Rule 1: `"Notify on task completion"` — trigger `task_completed`, empty conditions/actions
   - Rule 2: `"Auto-promote backlog tasks"` — trigger `task_created`, conditions `[{"field":"status","op":"eq","value":"backlog"}]`, actions `[{"type":"move","target":"todo"}]`
   Idempotent: skip if a rule with the same name already exists.

The function signature should be:

```python
def main(argv: list[str] | None = None) -> int:
```

With `argparse` arguments:
- `--database-url` — override database URL (falls back to `FLOW_DATABASE_URL` env var or default SQLite path)
- `--project` — project slug to create (default: `default`)
- `--dry-run` — print what would be created without writing to DB

Output format — print to stdout:
```
Flow bootstrap complete.

Project: default (created / already exists)
API key: admin-key (admin) — flow_xxxxxxxx...
API key: impl-key (implementer) — flow_yyyyyyyy...
Agent: smoke-test (created / already exists)
Workspace config: default (created / already exists)
Automation rule: Notify on task completion (created / already exists)
Automation rule: Auto-promote backlog tasks ( created / already exists)
```

For dry-run, prefix each line with `[DRY RUN]` and print what would be created (generate key but don't store it).

Important: **never write API key values to tracked files**. Only print to stdout. The caller is responsible for capturing and storing them.
