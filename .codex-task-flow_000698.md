# SCHED-03: Add Stale-Task Age Conditions and Scheduled Policy Examples

## Context

Flow has automation rules (`AutomationRule`) with conditions and actions. Currently, conditions support `status`, `project`, `priority`, `assignee`, `assignee_type`, `human_required`, `title`, and `latest_handoff` fields. SCHED-03 adds age-based conditions (time since `updated_at`, `created_at`, or `claimed_at`) and cron-triggered rule dry-run output.

## What Exists

### AutomationRule model (flow_app/models.py)
- `id`, `name`, `description`, `enabled` (Integer 0/1), `priority` (Integer), `trigger` (String)
- `trigger_config` (Text, JSON), `conditions` (Text, JSON), `actions` (Text, JSON)
- `last_run_at`, `created_at`, `updated_at`

### Rules engine (flow_app/rules_engine.py)
- `CONDITION_FIELDS` dict maps field names to accepted operators
- Currently supported fields: `status`, `project`, `priority`, `assignee`, `assignee_type`, `human_required`, `title`, `latest_handoff`
- Operators: `eq`, `ne`, `in`, `not_in`, `contains`, `gt`, `lt`, `gte`, `lte`, `exists`, `not_exists`
- `evaluate_conditions(task, conditions)` → bool — AND logic across conditions
- `emit_event(session, event_type, data, rule_id)` → list[dict] — matches rules, evaluates conditions, executes actions
- `execute_actions(session, rule, task, actions)` → list[dict]

### Task model (flow_app/models.py)
- `created_at`, `updated_at`, `claimed_at` — DateTime(timezone=True) fields
- `claimed_at` is nullable — only set when a task is claimed

### Runner (flow_app/runner.py)
- `_run_cron_rules(session, now, dry_run)` — fires cron-triggered rules
- RunResult now includes `cron_matches`, `recurring_materialized`, `recurring_skipped`

### Schemas (flow_app/schemas.py)
- `AutomationRuleCreate`, `AutomationRuleUpdate`, `AutomationRuleResponse`
- Conditions and actions are JSON strings in the model, parsed as lists of dicts at runtime

## What to Implement

### 1. Add age-based condition fields to CONDITION_FIELDS (flow_app/rules_engine.py)

Add these fields to `CONDITION_FIELDS`:

```python
"age_since_updated": {"operators": ["gt", "lt", "gte", "lte", "eq", "ne"]},
"age_since_created": {"operators": ["gt", "lt", "gte", "lte", "eq", "ne"]},
"age_since_claimed": {"operators": ["gt", "lt", "gte", "lte", "eq", "ne"]},
```

These are virtual fields — they don't exist as Task attributes. Instead, they compute the age in seconds from the corresponding timestamp to `now`.

### 2. Modify _evaluate_single_condition to handle age fields (flow_app/rules_engine.py)

When the field is `age_since_updated`, `age_since_created`, or `age_since_claimed`:

```python
if field.startswith("age_since_"):
    # Determine the timestamp attribute
    attr_map = {
        "age_since_updated": "updated_at",
        "age_since_created": "created_at", 
        "age_since_claimed": "claimed_at",
    }
    timestamp_attr = attr_map[field]
    timestamp = getattr(task, timestamp_attr, None)
    if timestamp is None:
        # claimed_at can be None — if so, age condition cannot be satisfied
        return False
    # Make both timezone-aware
    now = datetime.now(timezone.utc)
    if timestamp.tzinfo is None:
        timestamp = timestamp.replace(tzinfo=timezone.utc)
    age_seconds = (now - timestamp).total_seconds()
    actual = age_seconds
else:
    actual = getattr(task, field, None)
```

The value in age conditions is a number in **seconds**. This allows flexible thresholds:
- `"age_since_updated gt 86400"` → updated more than 1 day ago
- `"age_since_created gte 3600"` → created at least 1 hour ago
- `"age_since_claimed gt 172800"` → claimed more than 2 days ago

### 3. Add dry-run support for scheduled rule evaluation (flow_app/rules_engine.py)

Add a `dry_run` parameter to `emit_event()`:

```python
def emit_event(session, event_type, data, rule_id=None, dry_run=False):
```

When `dry_run=True`:
- Evaluate matching rules and conditions as normal
- Instead of executing actions, return the planned actions with task details
- Do NOT mutate any state (no task moves, no notes, no dispatches, no webhooks)
- Return format: `{"dry_run": True, "matches": [{"rule_id": ..., "rule_name": ..., "task_id": ..., "actions": [...]}]}`

This enables: `POST /api/automation-rules/{rule_id}/dry-run` → preview what a rule would do.

### 4. Add REST endpoint for dry-run (flow_app/routes/automation.py)

```python
@router.post("/automation-rules/{rule_id}/dry-run", response_model=dict)
def api_dry_run_rule(
    rule_id: str,
    db: Session = Depends(get_db),
    _actor: Actor = Depends(require_permission(Permission.RULES_EVALUATE)),
):
    """Preview what a cron/scheduled automation rule would do without side effects."""
```

This endpoint:
1. Fetches the rule by ID
2. Calls `emit_event(session, "cron", {"rule_id": rule.id, "rule_name": rule.name}, rule_id=rule.id, dry_run=True)`
3. Returns the planned actions

## Important Constraints

- Age values are in **seconds** (not minutes, hours, or days). This keeps the API consistent with the existing numeric operator pattern.
- `age_since_claimed` must handle `None` gracefully — unclaimed tasks (no `claimed_at`) should NOT match any age condition (return False).
- Dry-run mode must NOT create tasks, notes, webhooks, or mutate any state. It returns planned actions as data.
- Stale-task example rules must be `enabled=False` by default.
- Age condition evaluation needs a `now` parameter for testability — `evaluate_conditions` should accept an optional `now` parameter defaulting to `datetime.now(timezone.utc)`.
- The `emit_event()` function signature change (`dry_run=False`) must be backward-compatible.
