# HARDEN-BACKUP-01: Add backup/restore and automation pack import-export (flow_000708)

## Goal
Add SQLite backup/restore commands and automation pack export/import with validation and dry-run for production Flow instances.

## Context
- Flow is a FastAPI app using SQLAlchemy + SQLite (single database file).
- Existing CLIs: `flow-serve` (`flow_app/serve.py`), `flow-runner` (`flow_app/runner.py`), `flow-bootstrap` (`flow_app/bootstrap.py`), webhook CLI in `flow_app/webhook_cli.py`.
- Database engine is built via `flow_app/database.py` → `build_engine(default_database_url())`.
- Models: `flow_app/models.py` — AutomationRule, WebhookConfig, NotificationConfig, Agent, Runner, etc.
- Schemas: `flow_app/schemas.py` — serialization/validation Pydantic models.
- Repository: `flow_app/repository.py` — CRUD operations.
- Secret references: `flow_app/secrets_resolver.py` — `is_secret_reference()`, `redact_secret()`.
- Config: `flow_app/config.py` — `get_settings()`, `database_url` property derives SQLite path from `FLOW_DATA_DIR`.

## Implementation

### 1. SQLite Backup/Restore CLI (`flow_app/backup.py`)

Add a **new CLI entry point** `flow-backup` registered in `pyproject.toml` as:

```
flow-backup = "flow_app.backup:main"
```

#### `flow-backup backup`
- Creates a timestamped copy of the SQLite database file.
- Uses SQLite's built-in `.backup` mechanism: open the DB, then `connection.execute("VACUUM INTO '<path>'")` for a consistent snapshot without stopping the server (SQLite WAL-safe).
- Default backup directory: `<FLOW_DATA_DIR>/backups/`.
- File name: `flow-backup-YYYYMMDD-HHMMSS.db`.
- Print the backup path on success.
- `--output-dir` flag to override backup directory.

#### `flow-backup restore <path>`
- Restores from a backup file.
- **Must refuse if server is running** — check for lock file or fail with clear error message saying "Stop flow-serve before restoring."
- Copy the backup file to the database path (overwrite).
- `--dry-run` flag: validate the backup file is a valid SQLite database (open it, run `PRAGMA integrity_check`) but do NOT overwrite. Print what would happen.
- Print confirmation on success.

### 2. Automation Pack Export/Import (`flow_app/packs.py` + `flow_app/routes/packs.py`)

#### Pack Format (JSON)
```json
{
  "schema_version": 1,
  "name": "pack-name",
  "description": "...",
  "exported_at": "2026-06-05T...",
  "rules": [...],
  "agents": [...],
  "webhook_configs": [...],
  "notification_configs": [...]
}
```

Fields that are secrets (e.g., `WebhookConfig.secret`, `NotificationConfig.api_key`) must be:
- **Exported** as redacted references or omitted entirely (use `is_secret_reference()` and `redact_secret()` from `secrets_resolver.py`).
- **Imported** as-is — caller must set secrets via environment/file references before import.

#### Export API
- `GET /api/packs/export` — admin-only. Returns a pack JSON with all automation rules, agents, webhook configs, notification configs.
- Secrets are redacted using `redact_secret()` and replaced with `"***"` or `""` if empty.
- Query param `?download=1` sets `Content-Disposition: attachment; filename="flow-pack-<timestamp>.json"`.

#### Import API
- `POST /api/packs/import` — admin-only. Accepts pack JSON body.
- **Validation pass**: check `schema_version`, required fields, validate each entity against its Pydantic schema. Return `422` with detailed errors if invalid.
- **Dry-run mode**: query param `?dry_run=1` — run validation but do NOT write anything. Return summary of what would be created/updated.
- **Apply mode** (default): upsert entities by name/label. Existing entities with same name are updated; new ones are created. Skip entities with ID conflicts.
- Response: `{"imported": {"rules": N, "agents": N, ...}, "skipped": [...], "errors": [...]}`.

### 3. MCP Tool
- Add `flow_pack_export` and `flow_pack_import` MCP tools in `flow_app/mcp/dispatch.py`.
- Export takes no args, returns pack JSON string.
- Import takes `pack_json: str` and optional `dry_run: bool`, returns import summary.

### 4. Tests (`tests/test_backup.py`, `tests/test_packs.py`)

**test_backup.py:**
- `test_backup_creates_file` — backup produces a valid SQLite file in default dir.
- `test_backup_custom_output_dir` — `--output-dir` works.
- `test_restore_dry_run_validates` — dry-run validates but doesn't overwrite.
- `test_restore_dry_run_corrupt_file` — dry-run catches corrupt backup.
- `test_restore_actually_restores` — restore replaces DB, verifiable via query.
- `test_restore_refuses_if_lock_exists` — simulates running server by creating lock marker.

**test_packs.py:**
- `test_export_redacts_secrets` — webhook secrets and notification API keys are `"***"`.
- `test_export_download_header` — `?download=1` sets Content-Disposition.
- `test_import_dry_run` — validates but nothing written to DB.
- `test_import_applies_entities` — rules and agents created.
- `test_import_invalid_schema_version` — returns 422.
- `test_import_upsert_existing` — updates existing entity by name.
- `test_import_permission` — non-admin gets 403.
